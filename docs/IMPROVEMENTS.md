# 第一階段改進：章節紀錄與資源載入

依照《遊戲重構與改進建議》核對目前實際使用的入口 `index.html`。
目前已經有 core / data / minigames 分工、Loading 畫面與互動遊戲，
`story.js`、`game_level1.js` 並未由入口載入，故本次不擴充舊的拼圖示範。

## 本次行為

- 已完成／鎖定的章節會沿用既有 `chapterStatus` 儲存格式，在重新整理後保留。
- 關卡選單提供「重設章節進度」，確認後三章恢復初始開放狀態。
  此按鈕僅重設章節紀錄，不刪除其他系統的收藏或設定。
- 損壞的存檔、非預期欄位、無法使用的 localStorage 不會中斷遊戲啟動。
- 章節對話與選項的背景圖加入等待預載；開場影片從實際的 source 標籤取得。
- 載入項目去重、單一資源只計算一次；15 秒未完成會繼續遊戲，避免畫面一直卡住。
  失敗或逾時的圖片仍可能暫時缺圖，並未保證資源已成功下載。
- 新載入工作會取代舊工作的完成回呼，避免延遲回應切回舊場景。
- 移除不存在的 MemoryGame.js 引用，保留實際使用的 MemoryGameV2.js。
- Service Worker 快取版本升為 game-v4。既有頁面可能需關閉所有遊戲分頁再開啟以完成更新。

## 本次範圍與後續

儲存粒度為章節完成紀錄，不是對話行數或小遊戲中途續玩；年齡模式仍於每次啟動選擇，
並沿用原本兩種模式共用的章節紀錄。沒有更動劇情、美術與各小遊戲的玩法或計時規則。

完整 ES Modules 遷移需要同步處理 HTML 行內事件、window 介面、資料檔載入順序，
以及 Service Worker 離線相依，應另開一階段逐步遷移與驗證。
GameState.js 目前未接入入口，直接改寫它不會改善實際執行中的遊戲。
中途續玩則需先設計可序列化的對話分支、收藏、副作用與小遊戲狀態，避免載入後重複發獎或錯跳劇情。

背景圖收集、重複媒體事件、載入逾時、晚到事件與重疊載入。
尚未完成實際瀏覽器的整段遊玩、手機觸控與 PWA 更新／離線驗證。
合併前請在兩種模式走完三章、重新整理確認完成紀錄，並檢查重設按鈕與首次／重訪載入。

## 第二階段：保留 16:9，改善跨裝置排版

固定比例適合目前的場景構圖與固定座標小遊戲。新增 css/viewport.css，
舞台依可用寬高等比例縮放並水平／垂直置中，扣除四邊 safe-area-inset。
黑邊保留，不裁切或拉伸遊戲舞台。瀏覽器工具列尺寸變化使用動態視窗高度 dvh；
較舊瀏覽器保留 vh 降級。

支援容器查詢單位的瀏覽器會讓核心選單、對話與確認窗文字／間距依舞台高度調整，
較長對話與選項可在各自區塊捲動。角色原有百分比定位保留，選項原有 30% 頂部位置保留。
直向仍提示橫放；這不是完整的直向介面改版。防禦遊戲啟動時計算尺寸改以實際舞台為準。
Service Worker 快取升為 game-v5，納入新增樣式。

本機版面檢查工具：

```sh
node tests/serve-layout.cjs
```

開啟 http://127.0.0.1:4173/preview?w=844&h=390&scene=dialogue&safe=1
可模擬安全區域；w、h 為視窗尺寸，scene 可選 age、menu、dialogue、defense、memory。
測試伺服器僅監聽本機，對測試頁回應注入示範場景與尺寸檢查，不修改正式入口。

已在 Chromium 實際載入遊戲，檢查 568×320、667×375、844×390、1024×768、1920×1080、
2560×1080、390×844 的舞台比例、置中與邊界；模式、章節、對話及兩款小遊戲主要區塊未超出舞台。
844×390 另模擬左右各 44px、底部 21px 的安全區域。
這些是模擬尺寸下的 DOM 幾何與目視檢查，不代表已完成實體 iPhone／Android、Safari、
所有遊戲狀態或旋轉中的觸控驗證。防禦遊戲進行中的即時尺寸重排仍需後續處理。
